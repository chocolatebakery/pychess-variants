CHANGE SUMMARY
--------------

1. Separate Fairy-Stockfish-X engine
   - Add pyffish_fsx and a separately loaded ffish-fsx JS/WASM package.
   - Preserve the official and Alice engines and route variants explicitly.
   - Vendor corresponding FSX sources, browser binaries, types and GPL notices.
   - Build the Python extension from source on Linux/WSL instead of relying
     on the ABI of a wheel built on another machine.
   - Update dependencies, locks, static asset copying and Docker build inputs.
   - Install the local FSX Python package before the main application in the
     native Render build script; document the same order for manual pip builds.

2. Random Dice variants
   - Add Berolina, Extinction, Kinglet, Three Kings and Torpedo using the
     official engine.
   - Add Rifle Chess, Brotherhood, Spell Chess and Monster Chess using FSX.
   - Expand Random Dice from 18 to 27 equally weighted entries, pool version 7.
   - Exclude the four FSX entries when the Python FSX engine is unavailable,
     leaving 23 entries; never substitute ordinary chess rules for FSX.
   - Preserve Wild 29, the operating-system-backed draw, and the existing
     immediate-repeat exclusion for rematches.
   - Keep normal game creation limited to Wild 29 and Random Dice, without
     introducing independent ratings for the added variants.

3. Spell Chess
   - Add Freeze and Jump controls, target selection, cancellation, reserves,
     cooldowns and board markers.
   - Preserve complete spell-and-piece moves, promotions and extended FENs.
   - Preserve spell targets in PGN notation for unambiguous imports/replays.
   - Handle FSX board prediction and capture detection separately from chess.

4. Monster Chess
   - Load the FSX INI definition: White has a king and four pawns and moves
     twice; Black has its full army and moves once.
   - Automatically play the mandatory Black pass between White's moves.
   - Preserve passes in storage and PGN without charging Black's clock or
     granting Black an increment for the automatic pass.
   - Support takebacks, reloading and recovery after a pending forced pass.
   - Preserve the supplied FSX king-capture rules rather than replacing them
     with a different checkmate-based Monster implementation.

5. Manual test games
   - Add a separate lobby block for Monster, Rifle and Spell Chess against
     Random-Mover, with color and time controls.
   - Keep direct FSX bot games casual and use Random-Mover.
   - Disable computed FSX analysis/AI where the standard worker does not
     support these rules; retain manual analysis and replay.

6. Session scores and the original scoreboard
   - Add per-variant wins, draws and losses with totals and a reset control.
   - Store session scores per user and browser tab, surviving page reloads.
   - Avoid duplicate results and ignore archives, aborts and engine errors.
   - Keep Chess960 separate from ordinary chess in session totals.
   - Keep the original head-to-head crosstable FIRST on the game page.
   - Display the added session scoreboard BELOW the original crosstable.
   - Leave the original crosstable's data, behavior and visibility rules
     unchanged; do not replace it or alter ratings.

7. Visual assets
   - Integrate supplied variant logos with theme-aware SVG masks.
   - Add the Monster logo from new_icons/monster.svg.
   - Update Knightmate's marked royal knight and king-shaped commoners.
   - Add Berolina pawns and Spell Chess piece/potion assets and generated CSS.
   - Give Random Dice its dice logo while preserving the original dice SVG.

8. Documentation and regression coverage
   - Add FSX-no-Site.md and Recursos-Visuais.md.
   - Update README and Render installation instructions, including the
     continued requirement for an online MongoDB instance such as Atlas.
   - Add engine routing/rule tests, spell/Monster codecs and PGN coverage,
     game/reload/rematch tests, visual asset checks and session score tests.
   - Add regression tests for keeping the original scoreboard first.
